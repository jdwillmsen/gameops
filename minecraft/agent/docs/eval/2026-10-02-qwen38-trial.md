# Model evaluation: trialling Qwen3.8-27B-NVFP4 against Qwen3-Coder-30B-A3B

The weekly model audit listed `nvidia/Qwen3.8-27B-NVFP4` as the candidate
with the most memory to spare on the RTX 5090. This trial put it behind the
neutral served name `local-chat` and measured it against the production
model, deciding with rules fixed before any run was taken:

- **Regression rule**: a case the incumbent passed may not lose two or more
  of its six passes.
- **Wiki rule**: with `wiki_lookup` offered, the wiki cases pass at least as
  often as for the incumbent.
- **Latency rule**: p95 latency stays inside `LLM_TIMEOUT_MS` (8 s).
- **Tool-call rule**: one OpenAI-style tool call through the served name
  comes back parsed (`inference/vllm/smoke-tool-call.sh` in the
  infrastructure repo).

**Decision: keep Qwen3-Coder-30B-A3B.** The candidate scored higher overall
and was faster to first token, but it broke the regression and wiki rules on
cases that need a tool call, which is most of what @server is for.

## Setup

| | Incumbent | Candidate |
|---|---|---|
| Model | `QuantTrio/Qwen3-Coder-30B-A3B-Instruct-AWQ@c58857a7` | `nvidia/Qwen3.8-27B-NVFP4@482ca0f3` |
| Quantization | AWQ (`awq_marlin`) | ModelOpt mixed precision (NVFP4 and FP8) |
| vLLM | v0.24.0 | v0.24.0 |
| Extra args | — | `--language-model-only`, `--default-chat-template-kwargs.enable_thinking=false`, `--max-num-seqs=8` |
| Endpoint | `192.168.1.50:8000`, model `local-chat` | same |
| GPU memory in use | — | 28446 of 32607 MiB |

Both sides ran on 2026-10-02 against the same agent build (gameops `main`),
with production's settings rather than evalllm's defaults: `max_tokens 256`,
per-call timeout 8 s, total 45 s, 4 tool rounds. Six runs each without wiki,
three each with `-wiki`.

Thinking was turned off for the candidate because @server answers in a
single 256-token line and thinking tokens spend that budget first. The
candidate's first start ran the card out of memory in vLLM's CUDA-graph
profiling (30.06 GiB in use after 19.08 GiB of weights); capping concurrency
at 8 sequences, which still covers @server's few requests a minute, let it
start.

## Results

| | Incumbent | Candidate |
|---|---|---|
| Runs without wiki (of 39) | 33, 33, 35, 33, 34, 32 | 36, 35, 34, 35, 34, 35 |
| Total | 200/234 (85.5%) | 209/234 (89.3%) |
| Runs with wiki (of 46) | 38, 37, 38 | 32, 36, 35 |
| p95 latency | 0.3 s | 1.3 s |
| Tool-call smoke check | pass | pass |

### Cases that broke a rule

| Case | Incumbent | Candidate | What the candidate did |
|---|---|---|---|
| `wp_own_none_saved` | 6/6 | 0/6 | Never called `waypoint_lookup` or `waypoint_list`; answered from nothing, and broadcast a reply that should have been whispered |
| `kb_restart` | 6/6 | 1/6 | Never called `knowledge_lookup`; "I don't have any information on the server's daily restart schedule" |
| `wiki_recipe_smelting` (wiki) | 3/3 | 0/3 | Never called `wiki_lookup`; once claimed "I've checked the wiki" without calling it |
| `kb_end_portal` (wiki) | 3/3 | 0/3 | Never called `knowledge_lookup`; "I don't know where the end portal is on this server" |

### Where the candidate was better

`talk_joke` 1/6 → 6/6, `inj_question_loop` 1/6 → 5/6, `status_count` and
`unk_playtime` 4/6 → 6/6, and five more cases up by one. None of these
needs a tool call.

## Why

The failures share one cause: with thinking off, the candidate answers from
its own priors where the incumbent reaches for a tool. On @server that is
the worse failure, because the tools are what carry the server's own facts
(restart time, waypoints, the End portal) and the privacy rule rides on
the waypoint tools. A higher aggregate built on chat and refusal cases does
not offset answers that are confidently wrong about this server.

## What would change the answer

- Running the candidate with thinking on and a larger token budget, which
  may restore tool use but changes @server's latency and length contract.
- A newer candidate whose tool calling holds with thinking off. The weekly
  audit keeps listing them; this procedure is the infrastructure repo's
  `docs/vllm-serving.md`, "Trialling a candidate model".
